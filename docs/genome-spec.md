# Mixlings — Genome Spec v0.1

Single source of truth for the genetics. Two implementations must agree bit-for-bit:
- `engine-ts/` — reference + server (Cloud Functions) validation
- `MixlingsKit/` — Swift package used by the iOS app and widgets

Agreement is enforced by `engine-ts/golden/vectors.json` (generated by the TS engine, consumed by both test suites).

## 1. Genes

Each creature is diploid: every gene holds two alleles `[a, b]` (allele = integer variant index).

| # | Gene key    | Prototype variants | Notes |
|---|-------------|--------------------|-------|
| 0 | `body`      | 6  | shape; defines anchor points for other parts |
| 1 | `eyes`      | 8  | |
| 2 | `head`      | 8  | ears / horns / antenna / crest; variant 0 = none |
| 3 | `pattern`   | 6  | variant 0 = plain |
| 4 | `tail`      | 6  | variant 0 = none |
| 5 | `palette`   | 16 | base / shade / accent colours |
| 6 | `aura`      | 4  | variant 0 = none |
| 7 | `temper`    | 10 | personality, no art |

Variant names/indices match the approved art (`art/render.py`). Variant tables live in `engine-ts/src/catalog.ts` (`CATALOG`) and are mirrored in Swift. Each variant has:
- `dominance`: integer 1..9 (higher wins)
- `rarity`: 0 common, 1 uncommon, 2 rare, 3 legendary
- `mutationOnly`: boolean — never appears in starter creatures; only enters via mutation

## 2. Expression (phenotype)

For each gene, expressed variant = allele with higher `dominance`; tie → lower variant index.

## 3. Deterministic randomness

- Hash: **FNV-1a 32-bit** over the UTF-8 bytes of the input string.
  - offset basis `0x811C9DC5`, prime `0x01000193`, all math mod 2^32.
- PRNG: **mulberry32** seeded with the hash:
  ```
  next():
    s = (s + 0x6D2B79F5) mod 2^32
    t = s
    t = imul(t ^ (t >>> 15), t | 1)
    t ^= t + imul(t ^ (t >>> 7), t | 61)
    return ((t ^ (t >>> 14)) >>> 0)          // UInt32
  float() = next() / 2^32                     // [0,1)
  int(n)  = next() % n
  ```
  `imul` = 32-bit wrapping multiply; `>>>` = logical shift; all values UInt32.

## 4. Breeding

Input: `parentA`, `parentB` (each `{id: string, genome: [[a,b] x 8]}`), `nonce` (string issued by server), `unlockedMutations` (list of `{gene: int, variant: int}` the *initiating* player has earned, sorted by gene then variant).

1. Order parents so that `parentA.id < parentB.id` (byte-wise string compare). Breeding is symmetric.
2. `seed = fnv1a32(parentA.id + "|" + parentB.id + "|" + nonce)`; `rng = mulberry32(seed)`.
3. For gene g in 0..7 (in order):
   - `fromA = parentA.genome[g][rng.int(2)]`
   - `fromB = parentB.genome[g][rng.int(2)]`
   - child gene = `[fromA, fromB]`
4. Mutation: `roll = rng.float()` (always drawn, even with an empty list). If `unlockedMutations` is non-empty and `roll < 0.15`:
   - `m = unlockedMutations[rng.int(len)]`
   - replace allele index `rng.int(2)` of gene `m.gene` with `m.variant`.
   Otherwise no further rng calls.
5. Twin palette shift: child carries `paletteShift` keyed by owner (`Parent.owner`, falling back to parent id): `0` for the owner of parentA (after ordering), `1` for the owner of parentB; if both owners are equal only `{owner: 0}`. Rendering shifts hue slightly by `paletteShift`. (Shown in preview.)
6. Child id = `"c_" + hex8(fnv1a32(seed_hex + "|child"))` where `seed_hex` = 8-char lowercase hex of seed.

## 5. Rarity

`score = sum over genes of rarity(expressed variant)`.
Tier: `score <= 2` common, `<= 5` uncommon, `<= 8` rare, else legendary.

## 6. Starter creatures

`starter(playerId, slot)`: rng seeded with `fnv1a32("starter|" + playerId + "|" + slot)`; for each gene pick both alleles uniformly among variants with `mutationOnly == false` (`rng.int(count)` into that filtered list, in variant order).

## 7. Validation and anti-reroll (server)

The server is the only authority for breeding outcomes.

1. **Nonce is single-use and bound.** `previewBreed(offerId, myCreatureId)` issues one nonce per (offer, acceptor creature), stores it, and returns the preview. Re-requesting a preview for the same pair returns the SAME nonce (no rerolls). Cancelling burns the offer.
2. **Daily caps:** max 10 previews and 20 offers per player per UTC day; one commit per offer.
3. **Mutations are server-owned:** `unlockedMutations` are read from the player's server record (earned by server-time streaks/biomes/events); any client-sent list is ignored.
4. **Genomes are server-owned:** parents' genomes come from the server registry (`creatures/{id}`, signed at birth); the client never sends genomes for validation.
5. **Commit:** `commitBreed(breedId)` recomputes `breed(...)` with the stored nonce, creates both twin creatures in one transaction, assigns the global serial number from `combos/{comboKey}.count`, and sets the discoverer only if empty.
6. The Swift engine computes the same result locally only for instant preview rendering; the server result always wins.

## 8. Collecting (cards, seasons, discoverer, daily surprise)

Implemented in `engine-ts/src/collecting.ts` and mirrored in `MixlingsKit/Sources/MixlingsGenome/Collecting.swift`; covered by `collecting` in the golden vectors.

- **comboKey** = the 7 visible expressed variants (body, eyes, head, pattern, tail, palette, aura) as decimal, joined by `-`, e.g. `"4-7-1-3-0-15-1"`. Temper and palette shift are excluded.
- **generation** = `0` without parents, else `max(parent generations) + 1`.
- **Season** = id, inclusive `startDay`/`endDay` (`yyyy-MM-dd`), 10–15 `(gene, variant)` entries. An entry is found when any owned creature *expresses* it. Season 1 `s1` "Перша весна": 12 entries, 5 common / 4 uncommon / 3 rare, no mutation-only variants.
- **Daily surprise** (free, once per day, no purchase or re-roll path): `rng = mulberry32(fnv1a32("surprise|" + playerId + "|" + day))`; `roll = rng.int(100)`; `roll < 80` gives sparks `5 + rng.int(21)`, else cosmetic `SURPRISE_COSMETICS[rng.int(4)]`.
